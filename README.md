# 質問トレーナー　セーブ＆ロードver.

## 【1】制作アプリのタイトル

質問トレーナー（ゲーム版・セーブ＆ロードつき）

## 【2】制作アプリの説明

企業説明会での質問のしかたを練習するゲームに、途中保存と挑戦の記録を追加したアプリ

- 「問題を出す」を押すと、説明会の場面がランダムに出題される（全7問）
- 選択肢を選ぶと「企業からの見え方」のコメントと点数（+10／0／-10）が表示される
- 50点以上でクリア、-30点以下でゲームオーバー
- **課題4で追加**：途中でページを閉じても、次に開いたときに続きから再開できる（セーブ＆ロード）
- **課題4で追加**：クリア・ゲームオーバーの結果が「これまでの挑戦」に残る（日時・結果・何問で・何点）

公開URL：https://morishi0713y.github.io/question-trainer/

## 【3】工夫した点・こだわった点

### 課題4：localStorage でセーブ＆ロード

| PR | ブランチ | 内容 |
|---|---|---|
| #7 | `feature/save-load` | 途中のスコアと挑戦の記録を localStorage に保存・読み出しする |

- **2種類のデータを別々の key で保存**：途中のスコア（`question_trainer_save`）と、これまでの挑戦の記録（`question_trainer_records`）を分けました。ゲームが終わったら途中のデータだけ `removeItem` で消し、記録は残します。
- **オブジェクトと配列を JSON で保存**：途中のスコアは `{ score, count }` のオブジェクト、記録は `{ date, type, score, count }` を並べた配列にして、`JSON.stringify` で文字にしてから保存し、読み出すときに `JSON.parse` で戻しています。
- **ページを開いたときに読み出す**：セーブデータがあれば「前回の続きから再開しました」と表示し、スコアと回答数を戻します。記録は `for` 文で一覧にしています。
- **「何問でクリアしたか」を記録**：回答数を数えるようにしたので、同じクリアでも少ない問題数でクリアできたかを振り返れます。

課題3では「機能ごとにブランチを作る → commit → push → プルリクエスト → マージ」の流れで、少しずつ機能を足していきました。

- 最初に見た目を変えずにコードの中身だけを整理した（#1）ので、そのあとの問題追加（#2）は、データを足すだけで済みました。

### コードの工夫

- **問題データを1か所にまとめた**：課題2では `if (q === 0)…` の分岐がボタンごとに散らばっていましたが、1問を `{ question, choices: [{ text, comment, point }] }` というオブジェクトにまとめました。選択肢ボタン3つの処理も1つにまとめています。
- **同じ問題が続けて出ないようにした**：`do { … } while (next === q)` で、前の問題と同じ番号が出たら選び直すようにしました。
- **1問につき1回だけ答えられるようにした**：スコアを何度も稼げないように、答えたら選択肢を押せなくし、次の問題で元に戻すようにしました。
- **難しさを1か所で変えられるようにした**：クリアとゲームオーバーの点数を `CLEAR_LINE`・`GAMEOVER_LINE` という定数にしました。画面のルール表示もこの数字から作っているので、数字を変えれば表示も変わります。
- **終了画面を関数にまとめた**：クリアとゲームオーバーはメッセージと色が違うだけなので、`showEnd(type, message)` という1つの関数にしました。

### 見た目

- スコアを緑の丸いラベルで表示
- 答えたあとは他の選択肢を薄くして、選んだものだけ緑で残す
- クリアは緑、ゲームオーバーは赤の終了画面
