# 質問トレーナー　リッチver.

## 【1】制作アプリのタイトル

質問トレーナー（ゲーム版）

## 【2】制作アプリの説明

企業説明会での質問のしかたを、選択肢を選んで練習できるアプリです。
課題2で作ったものをもとに、課題3ではスコアとクリア／ゲームオーバーを追加して、シミュレーションゲームにしました。

- 「問題を出す」を押すと、説明会の場面がランダムに出題される（全7問）
- 選択肢を選ぶと「企業からの見え方」のコメントと点数（+10／0／-10）が表示される
- 50点以上でクリア、-30点以下でゲームオーバー
- 「もう一度挑戦する」で最初からやり直せる

## 【3】工夫した点・こだわった点

### 開発の進め方

課題3では「機能ごとにブランチを作る → commit → push → プルリクエスト → マージ」の流れで、少しずつ機能を足していきました。

| PR | ブランチ | 内容 |
|---|---|---|
| #1 | `feature/question-data` | 問題・選択肢・コメントを配列とオブジェクトにまとめる |
| #2 | `feature/more-questions` | 問題を3問から7問に増やす |
| #3 | `fix/no-repeat-question` | 同じ問題が続けて出ないようにする |
| #4 | `feature/score` | 選択肢に点数をつけてスコアを表示する |
| #5 | `feature/game-result` | クリアとゲームオーバーの判定を追加する |
| #6 | `docs/readme` | READMEを課題3の内容に更新する |

- 新しい機能は `feature/`、直しは `fix/`、文書は `docs/` と、ブランチ名で変更の種類がわかるようにしました。
- 最初に見た目を変えずにコードの中身だけを整理した（#1）ので、そのあとの問題追加（#2）は、データを足すだけで済みました。

### コードの工夫

- **問題データを1か所にまとめた**：課題2では `if (q === 0)…` の分岐がボタンごとに散らばっていましたが、1問を `{ question, choices: [{ text, comment, point }] }` というオブジェクトにまとめました。選択肢ボタン3つの処理も1つにまとめています。
- **同じ問題が続けて出ないようにした**：`do { … } while (next === q)` で、前の問題と同じ番号が出たら選び直すようにしました。
- **1問につき1回だけ答えられるようにした**：スコアを何度も稼げないように、答えたら選択肢を押せなくし、次の問題で元に戻すようにしました。
- **難しさを1か所で変えられるようにした**：クリアとゲームオーバーの点数を `CLEAR_LINE`・`GAMEOVER_LINE` という定数にしました。画面のルール表示もこの数字から作っているので、数字を変えれば表示も変わります。
- **終了画面を関数にまとめた**：クリアとゲームオーバーはメッセージと色が違うだけなので、`showEnd(type, message)` という1つの関数にしました。

### 見た目

- スコアを緑の丸いラベルで表示
- 答えたあとは他の選択肢を薄くして、選んだものだけ緑で残す
- クリアは緑、ゲームオーバーは赤の終了画面
